Trading Agent Bot is controlled entirely through Telegram. Once the bot is running, every monitoring, trading, and financial action is just a message away — no web dashboard, no SSH. The `TelegramListener` class registers each command handler at startup via `start_polling()` and also programmatically sets the Telegram **Bot Commands menu** so the command list appears natively inside the chat app. A persistent reply-keyboard at the bottom of the screen gives one-tap access to the eight most-used commands, while inline buttons on every status message let you navigate the full panel without typing anything.

<Warning>
Only the Telegram user whose numeric chat ID matches the `TELEGRAM_CHAT_ID` environment variable is permitted to operate the bot. Every handler calls `verify_user()` first; any other sender receives an `⛔ Acceso denegado` reply and the request is silently dropped. Set this value carefully — it is the single security gate for all trading operations.
</Warning>

## Monitoring & Status

<Accordion title="/start — Open the main panel">

Sends a welcome message and immediately renders the current global status message with the full inline keyboard. Also activates the persistent reply-keyboard at the bottom of the chat screen.

```
/start
```

**What you see:** A welcome banner followed by the `/status` panel — bot state (running / paused), trading mode, open positions, total equity in USD, and live CLP equivalent from the `CLPConverter` (sourced from `mindicador.cl`).

</Accordion>

<Accordion title="/status — Global status panel">

Renders the full multi-agent status panel showing capital, open positions, and a per-agent summary row for each of the four sub-agents.

```
/status
```

**Inline buttons available:**
- 🔄 Actualizar — refresh in-place
- 📈 Flujo de Caja — navigate to cashflow
- 👝 Billetera — navigate to wallet
- 📋 Matriz Activos — navigate to asset matrix
- 📊 Estadísticas / 🛡️ Bloqueos — stats and blocked-op history
- ⚡ Scalper T1 / 🚀 Momentum T2 / 🐋 Macro BTC/ETH / ⚠️ Especulativo T3 — agent detail views
- ⚙️ Modo de Trading — trading mode selector
- ⏸️ Pausar Bot / ▶️ Reanudar Bot — global pause toggle

</Accordion>

<Accordion title="/wallet / /billetera — Wallet holdings and P&L">

Displays liquid USDT balance, every active position with entry price, current price, and floating P&L, plus a historical realized-P&L table grouped by symbol.

```
/wallet
/billetera
```

Both aliases call the same `wallet_command` handler. In multi-agent mode the message is generated by `format_global_wallet_message()`, which shows the per-agent breakdown and a `coins_breakdown` row for each tracked pair.

**Example output:**
```
👝 Detalle de tu Billetera (Holdings)

💵 Saldo Disponible: $9.42 USDT
📊 PnL Flotante Total: 🟢 $0.18 USDT

Posiciones Activas:
🔸 SOL: 0.05000000
   Precio Compra: $145.20 USDT
   Precio Actual: $148.80 USDT
   PnL Activo: 🟢 $0.18 USDT (2.48%)

🏛️ Histórico de Ganancias Realizadas
🔸 BNB: 🟢 $0.07 USDT
```

</Accordion>

<Accordion title="/matriz / /activos — Asset matrix (ON/OFF table)">

Renders two tables: an **Economic Table** listing every tracked coin with its current USD balance and cumulative P&L, followed by an **Operational Table** showing ON (🟢) or OFF (🔴/⏸️) status per coin.

```
/matriz
/activos
```

A coin moves to OFF automatically when its balance reaches $0.00 USD, at which point the orchestrator dispatches a forensic report. The matrix is built from `format_matrix_message()` on the orchestrator.

</Accordion>

<Accordion title="/cashflow — Financial flow report and ROI">

Generates the full financial report: initial base investment, additional deposits, operating expenses, withdrawals, realized gains, unrealized (floating) gains, net P&L, liquid cash available, and net ROI percentage.

```
/cashflow
```

**Inline buttons:** 🔄 Actualizar, 👝 Ver Billetera, 🧹 Reiniciar PnL (opens confirmation), ⬅️ Volver a Estado.

</Accordion>

<Accordion title="/stats [hours] — Decision statistics">

Shows decision counts from the `DecisionLog` database table. Without an argument, counts decisions since the start of the current day **in Chile timezone** (UTC offset applied automatically). With a number, looks back that many hours.

<ParamField path="hours" type="integer" optional>
  Number of hours to look back. Omit for today (Chile time). Common values: `6`, `24`.
</ParamField>

```
/stats
/stats 6
/stats 24
```

**Output includes:** Total evaluations, HOLD (waiting), BLOCKED (risk-gated), BUY, SELL, and ERROR counts.

**Inline time-filter buttons:** 📅 Hoy ✅ · ⏱️ 6h · ⏱️ 24h

</Accordion>

<Accordion title="/why_block — Last 10 blocked operations">

Queries the `DecisionLog` table for the 10 most recent `BLOCKED` decisions, showing the coin symbol, Chile-formatted timestamp, and the exact block reason string.

```
/why_block
```

Also displays today's block count and the all-time historical total from the database, which helps spot recurring risk triggers at a glance.

</Accordion>

<Accordion title="/horarios / /horario / /hora / /time — Market hours and Chile↔UTC converter">

Shows the current time in both Chile (`America/Santiago`) and UTC, the configured high-volatility window (default `13:00–17:00 UTC`), its Chile equivalent, and whether the bot is currently in **ACTIVE** (1 m candles) or **PASSIVE** (5 m candles) mode based on that window.

```
/horarios
/horario
/hora
/time
```

The message is generated by `explain_schedule_message()` from `tradingbot/utils/tz.py` and explains exactly why Chile and server time differ.

</Accordion>

## Trading Control

<Accordion title="/mode [trend|target|scalper] — Change trading mode">

Without an argument, opens the inline **Trading Mode** selector with three buttons. With an argument, applies the change immediately and persists it to `config.yaml`.

<ParamField path="mode" type="string" optional>
  One of `trend`, `target`, or `scalper`. Omit to open the interactive mode-picker keyboard.
</ParamField>

```
/mode
/mode trend
/mode target
/mode scalper
```

| Mode | Behaviour |
|---|---|
| `trend` | Follows the EMA trend; exits on Stop Loss −2% |
| `target` | Holds until Take Profit is reached; never stops out |
| `scalper` | Closes at micro-gains of +0.5% |

</Accordion>

<Accordion title="/pause — Pause the entire system">

Sets `bot.paused = True`, which propagates to every sub-agent (except a SpeculativeAgent that was already in passive mode with 0% capital). Market rules are no longer evaluated until `/resume` is called.

You can also target a single agent by passing its alias:

```
/pause
/pause scalper
/pause momentum
/pause macro
/pause speculative
```

Aliases resolve to the full IDs: `scalper_t1`, `momentum_t2`, `macro_btceth`, `speculative_t3`.

</Accordion>

<Accordion title="/resume — Resume the entire system">

Sets `bot.paused = False` and re-enables all previously-active sub-agents. Accepts the same aliases as `/pause` for single-agent targeting.

```
/resume
/resume scalper
/resume momentum
/resume macro
/resume speculative
```

</Accordion>

<Accordion title="/buy <symbol> <amount> — Manual buy with confirmation">

Places a manual **BUY** market order. A confirmation inline keyboard appears; you must tap **✅ Confirmar Compra** within 30 seconds or the order is discarded.

<ParamField path="symbol" type="string" required>
  Trading pair in CCXT format, e.g. `BTC/USDT`, `SOL/USDT`.
</ParamField>

<ParamField path="amount" type="float" required>
  Quantity of the base asset to buy. Must be a positive number.
</ParamField>

```
/buy BTC/USDT 0.001
/buy SOL/USDT 0.5
```

<Note>
After tapping the confirmation button you have exactly **30 seconds** before the pending order expires and is automatically discarded. This window is enforced server-side using `time.time()` — refreshing the chat does not reset it.
</Note>

</Accordion>

<Accordion title="/sell <symbol> <amount> — Manual sell with confirmation">

Places a manual **SELL** market order. Before showing the confirmation keyboard, the bot checks your wallet balance; if the requested amount exceeds what you hold, the command fails immediately with an `❌ Saldo insuficiente` error.

<ParamField path="symbol" type="string" required>
  Trading pair, e.g. `SOL/USDT`.
</ParamField>

<ParamField path="amount" type="float" required>
  Quantity of the base asset to sell. Cannot exceed your current holding.
</ParamField>

```
/sell SOL/USDT 0.5
```

Same 30-second confirmation window applies.

</Accordion>

## Financial Records

<Accordion title="/deposit <amount> [note] — Record a deposit">

Adds the specified amount to the `DigitalWallet` balance and creates a `DEPOSIT` record in the `CashFlow` table. Use this to account for fresh capital added to the trading account.

<ParamField path="amount" type="float" required>
  Deposit amount in USD.
</ParamField>

<ParamField path="note" type="string" optional>
  Free-text description. Defaults to `"Depósito"` if omitted.
</ParamField>

```
/deposit 100 Recarga mensual
/deposit 50
```

**Reply:** `✅ Depósito registrado: +$100.00 USD | Nuevo Balance: $150.00 USD`

</Accordion>

<Accordion title="/expense <amount> [note] — Record an operating expense">

Deducts the amount from the `DigitalWallet` balance and records an `EXPENSE` entry. Use this for recurring costs such as VPS fees or API subscriptions.

<ParamField path="amount" type="float" required>
  Expense amount in USD.
</ParamField>

<ParamField path="note" type="string" optional>
  Free-text label. Defaults to `"Gasto Operativo"`.
</ParamField>

```
/expense 20 Pago VPS
/expense 5 Binance API
```

</Accordion>

<Accordion title="/monetizar / /monetize_asset — Liquidate asset to USDT">

Closes all open positions for the given asset, marks them as `CLOSED` in the database, credits the total USDT value to the `DigitalWallet`, and realises the cumulative P&L. If no open trades exist for the asset, a synthetic `ProfitHarvesting` trade record is created for audit.

<ParamField path="asset" type="string" required>
  Base asset symbol, e.g. `SOL`, `DOGE`. Slashes are stripped automatically.
</ParamField>

<ParamField path="price" type="float" optional>
  Optional override for the exit price. If omitted, the current market price from the `Portfolio` table is used.
</ParamField>

```
/monetizar SOL
/monetizar SOL 155.00
/monetize_asset DOGE
```

**Example reply:**
```
💰 MONETIZACIÓN EXITOSA: SOL

• Cantidad: 0.5000 SOL
• Precio Ejecución: $155.0000 USDT
• Total Acreditado: 🟢 +$77.50 USD
• Ganancia Neta (PnL): +$5.25 USD (+7.3%)
• Nuevo Saldo Líquido: $84.92 USDT
```

</Accordion>

<Accordion title="/reset_pnl — Reset PnL counter to $0 (with confirmation)">

Archives all `CLOSED` trades by changing their status to `ARCHIVED` (preserving audit history), which brings realized P&L and ROI back to `$0.00` and `0.00%`. Active positions and wallet balance are **not** affected.

```
/reset_pnl
```

An inline confirmation keyboard is shown first:
- ✅ Confirmar Reinicio PnL
- ❌ Cancelar

Confirmation can also be triggered from the `/cashflow` panel via the 🧹 Reiniciar PnL button.

</Accordion>

## Help & Navigation

<Accordion title="/help — Show all available commands">

Sends the full help text listing every available command with a one-line description each.

```
/help
```

</Accordion>

<Accordion title="/menu — Refresh the persistent keyboard">

Re-sends the persistent reply-keyboard to the bottom of the chat. Useful if the keyboard was dismissed or the chat was opened on a new device.

```
/menu
```

**Persistent keyboard layout:**

| | |
|---|---|
| 📊 /status | 👝 /wallet |
| 📋 /matriz | 📈 /cashflow |
| 📊 /stats | 🛡️ /why_block |
| 🕒 /horarios | ❓ /help |

</Accordion>
